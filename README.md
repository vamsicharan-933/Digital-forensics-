# Digital-forensics-# 🔎 Wireshark HTTP Credential Capture — Cybersecurity Lab

## 📌 Overview

**Wireshark** is a network protocol analyzer that can capture and inspect network traffic. In an **authorized lab environment**, it can be used to understand how sensitive information may be exposed when insecure protocols such as **HTTP, FTP, and Telnet** are used.

This project demonstrates how HTTP requests can be analyzed in Wireshark to identify form data transmitted over an intentionally vulnerable test website.

> ⚠️ **Ethical & Legal Notice:**
> Perform packet capture only on networks, devices, and applications that you own or have explicit permission to test. Do not capture or attempt to obtain real users' passwords or private information.

---

## 🎯 Objectives

* Learn the basics of packet capture using Wireshark.
* Understand HTTP network traffic.
* Identify `GET` and `POST` HTTP requests.
* Understand how HTML form data can appear in unencrypted HTTP traffic.
* Demonstrate why HTTPS is important for protecting credentials.
* Practice network analysis in a controlled cybersecurity lab.

---

## 🛠️ Requirements

* Wireshark
* Windows or Linux
* A test/lab network
* An intentionally vulnerable or locally hosted HTTP website
* Test credentials created specifically for the lab

## Step 5 — Understand GET and POST Requests

Web forms commonly use HTTP methods such as:

* `GET`
* `POST`

The method used depends on how the web application was designed.

## Step 6 — Analyze GET Requests

Use the following Wireshark filter:

```text
http.request.method == "GET"
```

This displays HTTP GET requests.

A GET request can contain parameters in the URL, for example:

```text
http://lab.example/login?user=test_user
```

However, whether login information appears in a GET request depends on how the application implements the form.

---

## Step 7 — Analyze POST Requests

If the test website uses a POST request, use:

```text
http.request.method == "POST"
```

Wireshark will display HTTP POST requests captured during the experiment.

Select the relevant request generated by the **authorized test website**.

You can then inspect the packet details and HTTP data fields.

For an intentionally vulnerable lab application, the submitted test form data may appear in the HTTP request because HTTP does not provide encryption.

Example lab data:

```text
username = test_user
password = LAB_PASSWORD
```

This demonstrates the security problem with transmitting sensitive information over unencrypted HTTP.
